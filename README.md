# ضربان‌یار — React

بازسازی صفحات عمومی [zarabanyar.com](https://zarabanyar.com/) با React 19 و Vite، بر اساس محتوای قابل مشاهدهٔ سایت در ۸ نوامبر ۲۰۲۶.

متن‌ها، تصاویر، لوگوها، فونت‌ها و استایل‌های مرجع داخل پروژه قرار دارند. صفحه‌ها JSX واقعی هستند و برای نمایش به وردپرس، iframe یا اجرای اسکریپت‌های سایت اصلی وابسته نیستند. مسیرها بدون رفرش کامل صفحه جابه‌جا می‌شوند و هر صفحه به‌صورت جداگانه بارگذاری می‌شود.

## اجرا

Node.js نسخهٔ 22.12 یا جدیدتر لازم است.

```powershell
npm.cmd install
npm.cmd run dev
```

آدرس پیش‌فرض: **http://127.0.0.1:5173/**

در لینوکس و macOS می‌توانید به‌جای `npm.cmd` از `npm` استفاده کنید. پسوند `.cmd` مشکل محدودیت اجرای فایل‌های PowerShell را در ویندوز برطرف می‌کند.

```powershell
npm.cmd run build
npm.cmd run preview
npm.cmd test
```

خروجی قابل استقرار در `dist/` ساخته می‌شود. build برای تمام مسیرهای شناخته‌شده فایل `index.html` مستقل می‌سازد؛ بنابراین باز کردن مستقیم و refresh صفحه‌های فارسی روی GitHub Pages هم کار می‌کند. آدرس‌های ناشناخته از `404.html` برنامه استفاده می‌کنند.

## انتشار خودکار روی GitHub Pages

اکشن `.github/workflows/deploy-pages.yml` با هر push به شاخهٔ `main` یا اجرای دستی، وابستگی‌ها را با `npm ci` نصب می‌کند، تست‌های واحد را اجرا می‌کند، سایت را می‌سازد و روی GitHub Pages منتشر می‌کند. توکن جداگانه‌ای برای deploy لازم نیست؛ اکشن از `GITHUB_TOKEN` خود گیت‌هاب استفاده می‌کند.

تنظیم اولیه در مخزن [MuhammadGolchin1/zarabanyar](https://github.com/MuhammadGolchin1/zarabanyar):

1. وارد [Settings → Pages](https://github.com/MuhammadGolchin1/zarabanyar/settings/pages) شوید.
2. در **Build and deployment → Source** گزینهٔ **GitHub Actions** را انتخاب کنید.
3. تغییرات پروژه و فایل اکشن را به `main` push کنید. اگر تغییرات قبلاً push شده‌اند، در [Actions → Deploy to GitHub Pages](https://github.com/MuhammadGolchin1/zarabanyar/actions/workflows/deploy-pages.yml) روی **Run workflow** بزنید.
4. پس از سبز شدن اجرای اکشن، لینک نهایی در نتیجهٔ مرحلهٔ deploy و صفحهٔ Pages نمایش داده می‌شود.

آدرس پیش‌فرض مورد انتظار: **https://muhammadgolchin1.github.io/zarabanyar/**

پس از این تنظیم، pushهای بعدی به `main` خودکار منتشر می‌شوند. در حساب رایگان، مخزن باید عمومی باشد تا GitHub Pages در دسترس باشد. این روش مطابق [راهنمای رسمی GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) است.

اکشن مسیر پایه را از تنظیمات Pages می‌گیرد؛ مسیرهای تصاویر، فونت‌ها، CSS و لینک‌ها همگی با آن هماهنگ می‌شوند. برای ساخت دستی با مسیر زیرپوشه در PowerShell:

```powershell
$env:VITE_BASE_PATH='/zarabanyar/'
npm.cmd run build
Remove-Item Env:VITE_BASE_PATH
```

در انتشار روی ریشهٔ دامنه، مقدار پیش‌فرض `/` است. تنظیم `base` مطابق [راهنمای Vite برای GitHub Pages](https://vite.dev/guide/static-deploy#github-pages) اعمال می‌شود. تست `tests/pages-deploy.test.mjs` خروجی واقعیِ زیرپوشه را با یک سرور استاتیک، بدون fallback سرور توسعه، بررسی می‌کند.

## رفتارهای پیاده‌شده

- منوی دسکتاپ و موبایل، مسیرهای فارسی، عقب/جلو مرورگر و صفحهٔ ۴۰۴ داخلی.
- اسلایدر چهار تصویری با تعویض خودکار هر ۵ ثانیه، توقف روی ماوس، حرکت با لمس و کلیدهای جهت؛ نمایش بدون فلش و نقطه، مطابق مرجع.
- ورود و عضویت تمام‌صفحه، انتخاب موبایل یا ایمیل و اعتبارسنجی شماره‌های فارسی و انگلیسی.
- فرم شناخت کودک، پرسشنامه‌های چندمرحله‌ای، اعتبارسنجی فیلدهای الزامی، حفظ پاسخ‌ها هنگام جابه‌جایی مراحل و نوار پیشرفت.
- تقویم شمسی رزرو با حرکت بین ماه‌ها، محاسبهٔ کبیسه با `Intl` و تاریخ به وقت تهران.
- انتخاب فایل صوتی و تصاویر با کنترل تعداد، نوع و اندازهٔ فایل‌ها.
- جستجوی پرسشنامه‌ها و سوالات متداول بازشونده با پشتیبانی از کیبورد.
- دیالوگ‌های قابل بستن با Escape و مدیریت فوکوس.

## ارسال مستقیم فرم‌ها به بله

پس از تکمیل آخرین مرحله و اعتبارسنجی فرم، مرورگر کاربر مستقیماً `sendMessage` ربات بله را برای هر دو چت‌آیدی `57163451` و `1618959021` فراخوانی می‌کند. این مسیر هیچ بک‌اند یا پراکسی‌ای ندارد و از `VITE_API_BASE_URL` استفاده نمی‌کند. آدرس ربات و مقاصد در `src/lib/bale-config.mjs` تنظیم شده‌اند.

پیام شامل عنوان فرم، تاریخ به وقت تهران، کد ارسال، عنوان مرحله‌ها و متن سؤال‌ها و پاسخ‌هاست. برای گزینه‌های انتخابی، عنوان گزینه ارسال می‌شود. فرم‌های طولانی به پیام‌های شماره‌دار تقسیم می‌شوند؛ درخواست‌های هر مقصد به ترتیب و دو مقصد هم‌زمان ارسال می‌شوند. در خطای شبکه، پاسخ‌ها حفظ می‌شوند و تلاش مجدد بخش‌هایی را که درخواستشان قبلاً کامل شده تکرار نمی‌کند. ارسال فقط با پایان فرم انجام می‌شود، نه با تغییر فیلد یا ورود به مرحلهٔ بعد.

درخواست‌ها `POST` با `URLSearchParams` و `mode: 'no-cors'` هستند. در بررسی اتصال، توکن و دسترسی هر دو چت معتبر بودند، اما API بله هدر CORS لازم را برنمی‌گرداند. بنابراین پاسخ در مرورگر `opaque` است: مرورگر پایان درخواست را می‌بیند، ولی نمی‌تواند مقدار `ok` یا خطای خود بله را بخواند. پس از ارسال، فرم و پاسخ‌ها در صفحه باقی می‌مانند و متن وضعیت یا پیام موفقیت نمایش داده نمی‌شود.

چون وب‌سرویس انتخاب‌شده `sendMessage` است، برای پیوست‌ها نام و اندازهٔ فایل در متن قرار می‌گیرد؛ خود فایل صوتی یا تصویر آپلود نمی‌شود. قالب و مراحل قبلی فرم حفظ شده‌اند.

قرارداد API مطابق [مستندات رسمی بله](https://docs.bale.ai/#sendmessage) پیاده‌سازی شده است. تست‌ها درخواست‌های ارسال پیام را شبیه‌سازی می‌کنند و پیام واقعی به چت‌ها نمی‌فرستند. `scripts/check-bale-browser.mjs` نیز فقط با `getMe` و `getChat` اتصال را بررسی می‌کند.

## اتصال اختیاری ورود و رزرو به بک‌اند

سرویس پیامک، احراز هویت، پروندهٔ کودک، پرداخت و ثبت واقعی نوبت از صفحات عمومی سایت قابل استخراج نیستند. این بخش‌ها همچنان برای عملکرد واقعی به سرویس جداگانه نیاز دارند. تنظیم زیر صرفاً برای ورود و نمایش زمان‌های رزرو است و ارسال فرم به بله مستقل از آن انجام می‌شود.

برای اتصال به سرور، `.env.example` را به `.env` کپی کرده و آدرس سرویس خودتان را تنظیم کنید:

```dotenv
VITE_API_BASE_URL=https://your-api.example.com
```

قرارداد پیشنهادی آداپتور در `src/lib/api.js`:

| درخواست | دادهٔ ارسالی | پاسخ مورد انتظار |
| --- | --- | --- |
| `POST /auth/request-code` | JSON شامل `identity`, `method`, `register`, `name`, `password` | پاسخ موفق JSON پس از ارسال واقعی کد |
| `POST /auth/verify` | JSON شامل `identity`, `code` | JSON کاربر؛ نشست از طریق کوکی امن |
| `GET /appointments/availability?date=YYYY-MM-DD` | تاریخ میلادیِ معادل روز انتخاب‌شده | `{ "slots": [{ "id": "slot-id", "label": "۱۰:۰۰ تا ۱۱:۰۰" }] }` |

خطاهای سرور با کد HTTP ناموفق و JSON به شکل `{ "message": "پیام خطا" }` برگردند. درخواست‌ها از `credentials: 'include'` استفاده می‌کنند؛ در صورت جدا بودن دامنهٔ API، CORS و کوکی باید در سرور تنظیم شود. اطلاعات حساس و کلید سرویس پیامک نباید در متغیرهای `VITE_` قرار بگیرند.

## ساختار

```text
src/
  App.jsx                    مسیریابی و پوستهٔ برنامه
  routes.json                مسیرها و عنوان هر صفحه
  pages/                     JSX صفحه‌های مستقل
  components/
    Header.jsx, Footer.jsx   بخش‌های مشترک
    Interactions.jsx         فرم‌ها، اسلایدر، جستجو و دیالوگ‌ها
    LoginModal.jsx           ورود و عضویت
    JalaliCalendar.jsx       تقویم شمسی
  lib/
    api.js                   اتصال API و اعتبارسنجی
    bale-config.mjs          آدرس ربات و دو مقصد بله
    bale.mjs                 تبدیل سؤال‌ها و پاسخ‌ها و ارسال از مرورگر
    calendar.mjs             محاسبات تقویم
public/
  assets/original/            تصاویر، فونت‌ها و استایل‌های محلی
  styles/                    استایل هر صفحه با ترتیب مرجع
  app.css                    استایل رفتارهای React
reference/                   نسخهٔ مرجع، فهرست مسیرها و منشأ فایل‌ها
scripts/                     ابزارهای استخراج، تبدیل و بررسی بصری
tests/                       آزمایش مرورگر و تقویم
```

برای ویرایش روزمره مستقیماً فایل‌های `src/` و `public/app.css` را تغییر دهید. اجرای `scripts/generate-react.py` صفحه‌های JSX استخراج‌شده را دوباره می‌سازد و ویرایش دستیِ آن صفحه‌ها را بازنویسی می‌کند؛ اجرای آن برای توسعه یا build لازم نیست.

استایل‌های اصلی به‌صورت فایل‌های جداگانه وارد می‌شوند تا مرز استایل‌ها و ترتیب آبشاری مرجع حفظ شود. فایل `reference/failed-assets.json` منابعی را ثبت می‌کند که در خود سایت اصلی ۴۰۴ یا دامنهٔ نامعتبر داشتند. منابع شکسته به درخواست بیرونی در زمان اجرا تبدیل نمی‌شوند.

## آزمون‌ها

`npm.cmd test` از مرورگر Chrome یا Edge نصب‌شده برای بررسی مسیرها، نمایش موبایل، فرم‌ها، ورود، جستجو و تقویم استفاده می‌کند. در محیط دیگر، مسیر مرورگر را با متغیر `BROWSER_EXECUTABLE_PATH` مشخص کنید؛ یا مرورگر Playwright نصب‌شده در سیستم در دسترس باشد.

اسکریپت اختیاری `node scripts/qa.mjs` پس از اجرای dev server روی پورت ۵۱۷۳، تصویر صفحه‌ها و گزارش درخواست‌ها را در `test-results/` می‌سازد.
